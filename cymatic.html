What is actually computed

Separating ∇²u + k²u = 0 on a disc gives u = Jm(kr)·cos(mθ). Clamping the rim at radius a forces Jm(ka) = 0, so the admissible wavenumbers are k = jm,n/a, where jm,n is the n-th zero of Jm. Those zeros set the frequencies: every ratio in the spectrum is jm,n/j0,1, which is why a drum is not harmonic.

Jm is evaluated from its integral form Jm(x) = (1/2π)∫−ππ cos(mτ − x sin τ) dτ by the trapezoid rule on a full period. The integrand is analytic and periodic, so that rule converges spectrally — the error falls off exponentially in the number of points, and there is no truncation order to tune. The zeros are then found by Newton's method from McMahon's asymptotic estimate, iterated until the step stops changing.

The count is checked, not assumed: N=64 looked converged on small arguments and was still wrong by 8.8e−7 at x=40. The page uses 128 points, measured below against reference values at 25 digits.

The bug this replaces

This page exists because the engine it came from, vedic_cymatic_pde_engine.py, computed its "radius" like this:

r = safe_inverse_distance(r_sq)  →  1 / (r² + 1e-12)
r = 1 / r  →  r² + 1e-12

The variable named r held r squared, and an epsilon was added on every evaluation whether or not the point was anywhere near the centre. That value was then fed to Jn and used as the denominator of cos θ. At the lattice point (3,4) the mode value should be 0.3977; the old code returned −43.70. The patterns it drew were not Helmholtz modes.

There was never a singularity to suppress. It was manufactured by dividing by r to get cos θ. Here nothing divides: at the centre Jm(0) = 0 for every m ≥ 1, which annihilates the undefined angle on its own, and J0(0) = 1 pairs only with m = 0, where θ never appears.
