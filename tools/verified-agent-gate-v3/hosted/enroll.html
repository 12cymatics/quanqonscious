Verified Agent Gate · Browser setup

Set up your signing authority

Use your browser to configure the gated runner in 12cymatics/quanqonscious. GitHub supplies the Linux runner; you do not need a Linux computer or a terminal.

Generate a new Ed25519 key here, then enroll its public fingerprint separately in GitHub. This page contains no supplied authority key.

Open a copy of this page whose source you trust. A fingerprint identifies a public key; a fingerprint supplied by an untrusted page does not establish the key's origin.

The key-generation code makes no network requests and does not use browser storage, external libraries, or telemetry. It uses your browser's native WebCrypto implementation. The links below open GitHub or OpenAI only when you choose them. No OpenAI API key is entered on this page.

1. Generate a new authority

A modern browser with native Ed25519 support and a secure context is required. Open this trusted downloaded HTML file directly, or serve the trusted file over HTTPS. If your browser does not support the required features, generation stops with an error.

No key has been generated.

2. Enroll the fingerprint and secret separately

In 12cymatics/quanqonscious, open Settings → Environments. Create or open the environment named verified-gate. Set its deployment branches to the reviewed trusted branch you will run. If required reviewers are configured, their approval is needed before the job receives its secrets.

Open GitHub environment settings

Save the fingerprint under Environment variables → Add variable and the private key under Environment secrets → Add secret, using the exact names below. Keep the fingerprint in a separate trusted record so you can check later receipts. This page does not configure GitHub for you.

PUBLIC · ENVIRONMENT VARIABLE

64 lowercase hexadecimal characters: SHA-256 of the 32 raw public-key bytes.

PRIVATE · ENVIRONMENT SECRET

Standard Base64 encoding of the 32-byte private seed. Anyone holding this secret can sign as this authority. Paste it only into the intended GitHub Actions secret or your trusted secret manager; never into a repository file, issue, workflow input, or chat.

Public verification key and format

WebCrypto generates the key pair. The private seed is the Base64url-decoded d member of the exported Ed25519 JWK, re-encoded as standard Base64. The public key is exported in raw format. The page imports the exported seed again and verifies a test signature before displaying the results.

3. Add your OpenAI API key in GitHub

Open your OpenAI API project and create a project API key for this runner. In the same GitHub environment, verified-gate, save that value as the environment secret OPENAI_API_KEY. Enter it directly in GitHub; this setup page never asks for or receives it.

Open OpenAI API keys Open GitHub environment settings

The API project needs available API credits. Eligible ChatGPT Pro and Business subscriptions may claim included credits through OpenAI's current benefit. A ChatGPT login does not automatically provide this workflow with a project API key. Check eligibility and activate API credits.

4. Run a task in GitHub

After the reviewed workflow is on the repository's default branch and the environment is configured, open Actions → Verified Agent Gate → Run workflow. Choose the reviewed branch, enter the requested task and a model available to your API project, then start the run.

Open the gate workflow

The workflow file is .github/workflows/verified-agent-gate.yml; the controller source is under tools/verified-agent-gate-v3. Opening this link does not start a run. The live run must pass its checks before any model-requested work is dispatched, and its results appear on that run's GitHub page.

5. Save, then clear

The key exists only in this page's live memory until you copy or save it. Generation does not copy, download, submit, or enroll anything automatically.

After saving both authority values, choose Clear this page and close the tab. The page also clears its values and references when the browser delivers its page-leave event. It cannot guarantee physical memory erasure, clear your clipboard, remove saved copies, or control browser extensions and device backups.

Clearing before saving loses this key. Generating another authority creates a different identity and does not update GitHub automatically.
